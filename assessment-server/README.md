# V2.11 个人测评 · 可移植 Node / Express / SQLite 版本

## 直接下载 PDF（2.11-report-5）

报告页“导出PDF”从已登录后端生成文件并直接下载，不调用浏览器打印，也不需要用户设置纸张或缩放。沿用认可模板的字体、留白与色系，并按授权更新为四领域：标准 V2.11 合成报告约10页，长自由文本和历史重算提示按需续页，页码自动包含续页。文字可选择/搜索，分数条及雷达为矢量绘制；不是页面截图。

- 本人：`GET /api/assessments/:id/pdf`；管理员：`GET /api/admin/assessments/:id/pdf`。
- 沿用 Better Auth 会话和不可变管理员账号ID。本人查询绑定 `id + user_id`，管理员经过现有管理员权限中间件；不存在/越权404、无登录401、非管理员403。界面还发送当前账户绑定头，切换账户后拒绝旧页面下载。
- 服务端从数据库原始答案经 `readStoredReport` / `presentReport` 读取当前报告，忽略客户端传入的分数/报告/身份查询参数。不改写答卷、计时、历史快照、用户或草稿。管理员成功导出只记录 `export-pdf` 的管理员ID、报告ID和时间，不记录PDF内容。
- 返回 `application/pdf`、`attachment`、RFC 5987中文文件名、`Cache-Control: no-store`、`X-Report-Export-Version: 2.11-report-5`。文件名清理路径和控制字符；PDF在内存中生成，不创建公共链接、不保存服务器临时报告、不发送第三方。
- 生成器是 `report-pdf/render_report.py`，通过无shell子进程接收后端JSON。最多同时生成2份，繁忙或30秒超时返回503，按钮可重试；单个输出上限20MiB。失败不会返回空白伪PDF。浏览器关闭/离开报告时取消下载。

### 运行依赖

Dockerfile已加入 Debian 官方 `python3` 与 `python3-reportlab`，并复制私有字体和生成器。保留现有 `.env`、数据库数据卷、登录配置及反向代理规则。无需Chromium、浏览器打印权限或运行时字体下载。Docker镜像需重新构建，不能只替换静态文件：

```sh
docker compose up -d --build
```

不使用Docker的 Debian/Ubuntu 部署须先安装运行依赖：

```sh
sudo apt-get update
sudo apt-get install -y python3 python3-reportlab
python3 -c 'import reportlab; print(reportlab.Version)'
npm ci --omit=dev
npm start
```

`report-pdf/fonts/` 随包包含基于 OFL Noto Sans CJK SC 转换的完整Unicode字符映射TrueType字体及许可证，约24MiB；不以示例/用户字符做静态子集。生成PDF时只嵌入本次所需字形。`scripts/build-report-fonts.py` 是维护时一次性字体转换工具（需 fonttools 与本机 fonts-noto-cjk），部署不需要执行或安装fonttools。字体只供后端读取；报告页面不再加载旧打印组件/字体。罕见补充平面汉字采用正确UTF-16BE ToUnicode映射。

下载路径相对于当前应用目录生成，支持根路径和 `/ceping202610/`；继续沿用同源鉴权/代理，PDF接口无需新增跨域地址或公开目录。原Cloudflare Worker版本不能运行Python，因此本次服务端生成器仅适用于 `assessment-server`，不能把它直接复制为Worker依赖。

cd assessment-server
cp .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# 将上一步输出填入 .env 的 AUTH_SECRET，勿公开或提交它

浏览器打开 http://localhost:3000。注册账号后开始作答。Windows 也需安装 Python 3 和 ReportLab，并确保服务进程可执行 `python3`；Linux/macOS 配好 `.env` 和 Python 依赖后可运行 `./start.sh`。

## 有什么

- 邮箱+密码注册、登录、退出。密码至少6字符，由 Better Auth 处理哈希和会话，不自制认证。
- 原题目、选项与分维度计分原样保留在 `private/`；职业性格总分另用明确版本化的岗位权重。浏览器仅从登录保护 API 取得题干/选项。
- 开始时说明服务器保存；按页点击提交后保存进度、锁定该页。刷新/重新登录可以继续。不会读取或上传旧版 localStorage。
- 点击最终提交后，后端校验答案并计算；不接受客户端分数、权重、参照参数。
- 普通账号只看到自己的草稿/历史报告；可显式配置唯一管理员只读查看全部已完成报告。报告保存当时的版本与完整快照。历史报告原始记录不改写；职业性格总分按已存七维作当前岗位解释，工作价值观分项按匹配版本的原始作答补充展示，详见末尾版本说明。
- 报告显示中文维度名及高低分含义，不展示典型题与回答。API不公开权重、计分表、逐题贡献、内部计算轨迹。
- 没有编辑/删除他人记录功能、团队、多租户、支付、配额、邀请或邮件服务。

## 搬到自己的 Linux 服务器：Docker 单容器

先复制**整个项目文件夹**，设置 `.env` 中随机密钥与真实域名：

```dotenv
NODE_ENV=production
APP_ORIGIN=https://assessment.your-domain.com
AUTH_SECRET=自行生成的随机密钥
```

然后运行：

```sh
docker compose up -d --build
```

SQLite 使用 `assessment-data` 持久卷；重建容器不丢数据。不要执行 `docker compose down -v`，它会删除数据卷。

示例使用 Linux Docker 的 host 网络，服务仅绑定服务器 `127.0.0.1:3000`（没有公开端口映射）。此 Compose 适用于 Linux 服务器；Windows/macOS 本地开发请用 npm。在服务器上安装/配置您已有的 HTTPS 反向代理，将域名反代到此地址。提供 `Caddyfile.example`；更换域名、设置DNS并允许80/443，Caddy管理证书。也可用现有 Nginx 或其他可靠代理。**必须先配置 HTTPS，再给真实用户使用**；生产会话 Cookie 为 Secure，HTTP 下无法正常登录。

`APP_ORIGIN` 必须精确等于浏览器地址的源（协议+域名+可选端口），无末尾斜杠，无路径。APP/API 同源，不需要 CORS。

提供的 Compose 使用 `TRUST_PROXY=loopback`，只信任同一台服务器上的回环反向代理；配套 Caddy 强制覆盖 X-Forwarded-For。应用将 Express 验证后的客户IP传给认证限流，忽略用户自行传入的内部IP头，因此不同员工不会共享一个容器网关限流桶。必须使用此配套架构，且保持 HOST=127.0.0.1、代理和应用同主机。不要将3000对外绑定，不要直接信任所有代理。主机上的其他进程属于受信任边界。此示例不含 CDN 或前置代理；如果接入，必须重新验证真实客户端IP。共享同一公网NAT的用户仍共享IP限流桶，认证总入口默认每IP每分钟120次，另保留认证库登录端点的更严格保护；可用AUTH_RATE_LIMIT（20—1000）调整总上限。集中大批注册需先做容量与限流设计，不保证无限并发。若更换网络架构，需重新配置并验证可信代理。

`DATA_DIR` 必须为服务专用目录，Linux 权限0700；数据库新文件0600。默认项目data目录启动会收紧权限；自定义已有目录不安全时启动拒绝，请确认这是专用目录后自行执行 `chmod 700 路径`。不要将DATA_DIR设为家目录或其他共享目录。

## 本地/服务器数据、备份与迁移

本地数据默认 `data/assessment.sqlite`，含用户、会话、草稿、答卷及报告；WAL运行时可能有 `-wal/-shm` 文件。不要在运行时只拷贝主数据库文件。

最简单的可靠备份：短暂停服务，完整复制数据，再启动。

本地 Node：停 `npm start`，复制整个 `data/` 到安全备份位置，然后重新 `npm start`。

Docker：

```sh
docker compose stop app
mkdir -p backups
# 停服后卷内数据库没有写入；命令会启动一个一次性容器打包持久卷
# 包含所有SQLite文件，文件所有者按卷原样保留
docker compose run --rm --no-deps --user root -v "$PWD/backups:/backup" app sh -c 'tar czf /backup/assessment-data.tar.gz -C /app/data .'
docker compose start app
```

恢复/迁移：停服，将备份完整还原到同一 `data/` 或Docker持久卷，再启动。先在隔离环境做恢复演练，核对账号、草稿和历史报告。保留原 `.env` 密钥（单独安全保管）；迁移时域名变化需更新 `APP_ORIGIN`。不要将含真人数据的数据库、密钥或备份放入可下载项目包/公开仓库。

**SQLite适用于单实例、小规模、适度并发**，不是高并发分布式方案。不要多个容器/主机同时挂同一数据库，也不要把数据库放共享网络文件系统。更大规模需正式迁移数据库并压测。

## 安全与边界

- 所有测评/草稿/历史API需会话，SQL同时限定当前账号。仅登录/注册等认证接口公开。
- 对变更请求严格检查 Origin；Better Auth保留CSRF校验；会话HttpOnly/SameSite=Lax，生产Secure。
- 限制请求大小、登录/API频率与答案字段；密码由认证库哈希。认证日志关闭，业务日志不记录答案/凭据。
- 生产缺失随机密钥、非HTTPS源会拒绝启动；源码不包含秘密。
- 原始答卷与报告在服务器磁盘上**没有应用层加密**。服务器管理员和获得数据库备份者可读取，请使用磁盘加密、最小权限、加密备份与访问审计。
- 邮箱只是登录标识，**未验证邮箱所有权**；未配置邮箱验证、找回密码、MFA。忘记密码目前无法自助找回；不提供不安全的绕过登录方案。正式开放前按实际需要接入邮件服务并审核隐私告知/保留政策。
- 家庭题选填，可能涉及家人和未成年人；不需要的信息请留空。上线方负责真实数据收集告知、保留期限及删除请求处理。
- 题目对已登录答题者可见，这是作答必要条件；不能承诺防止抄题。登录用户可重复答卷，结果可用于推测部分规则；这不是防逆向/高强度考试防作弊系统。
- 计时由浏览器提供，服务器只校验格式与范围，无法验证实际耗时。分数在后端可信计算，不代表输入不可伪造。
- V2.9参照来自合成模拟，不是经真实人群验证的常模；仅个人探索，不构成诊断或招聘/淘汰依据。

## 唯一只读管理员

默认 `ADMIN_USER_ID` 为空，所有账号都是普通账号。不会把首个注册账号、姓名为admin的账号或某个邮箱自动升级。

1. 在登录页自行注册，姓名可以填 `admin`；仍使用邮箱登录。请设置一个全新的密码，不要在聊天或文件中提供密码。
2. 注册登录后可点击“复制账户编号”获取自己的不可变ID。也可由服务器管理员在项目目录运行 `npm run account-id -- 注册邮箱`，只读取该账号的ID/姓名/邮箱，不输出密码或会话。Docker使用 `docker compose exec app npm run account-id -- 注册邮箱`。
3. 核实身份，将输出的不可变用户ID填入 `.env` 的 `ADMIN_USER_ID`，然后重启服务。Docker需 `docker compose up -d --force-recreate` 重新加载环境；原SQLite数据卷不变。
4. 登录该账号后会出现“管理历史”，可以只读打开所有已完成报告和原始逐题作答详情；不能修改或删除别人的答案和报告，不提供他人未提交草稿。

列表/报告读取写入SQLite `admin_audit`：仅管理员ID、操作、报告ID和时间，不写答案、报告内容、密码或会话。将ADMIN_USER_ID清空并重启即撤销此权限。改姓名/邮箱或重新注册同名账号不会继承管理员权限。

管理员可读取他人的报告和报告内个人信息；部署方应提前告知受测者访问范围并遵守相应数据保护要求。

## 流畅逐页填写
确认后立即进入下一页，冻结本页快照并放入单一内存队列，按顺序后台保存。界面分别显示确认页数和服务端已保存页数；网络失败/15秒超时保留原请求，显示重试入口。最终报告等待所有页面保存成功后再提交。关闭页面会提示未完成内容；不在浏览器持久存储敏感答案。会话过期时仅在当前页面内按原账户保留未保存状态，同账户重新登录后恢复；不同账户不能重放，开始/恢复另一份测评须明确确认丢弃旧状态。仅服务端确认保存的页面可在关闭浏览器后恢复；网络失败尚在内存队列的内容不能保证关闭后保留。

写入草稿、提交报告和清理草稿时，请求附带该份作答最初绑定的账户ID，后端始终将其与真实会话ID比较。若另一个标签页切换了登录账户，旧页面的保存会暂停并要求原账户重新登录，不会把旧账户答卷写入新账户。此请求头仅用于一致性校验，不能授予权限；身份仍完全由Better Auth会话确定。

更新后仍未刷新且不携带账户绑定头的旧页面会收到409并停止写入。先保留尚未保存内容，再刷新页面继续；不要直接关闭存在未保存答案的旧页面。

### 首页解释规则（report-5）

`report-summary.js` 为职业稳定性、职业性格、心理困扰倾向分别提供五档独立解释，避免把“平均”简单解释为分项均衡；24项维度均有高/低方向的简短语义。总体概述每个领域最多选一个重点，按该指标自身参照中心到对应上/下界的宽度标准化偏离，只用于选择解释重点，不改变任何分数、标签或计分公式。
